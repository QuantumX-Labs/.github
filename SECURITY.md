## 1. Our Security Commitment

At **QuantumX Labs**, security is an essential part of responsible technology development.

We are committed to building software, applications, infrastructure, and intelligent systems with security, privacy, reliability, and transparency in mind.

As an independent technology research and development initiative, we recognize the importance of identifying vulnerabilities, addressing security weaknesses, and encouraging responsible security research.

We welcome responsible vulnerability disclosures from security researchers, developers, and members of the open-source community.

Our objective is to maintain a secure and trustworthy technology ecosystem.

---

## 2. Supported Security Issues

We encourage responsible reporting of security vulnerabilities affecting QuantumX Labs projects and infrastructure.

Examples of security issues include:

| Category | Examples |
|---|---|
| Application Security | SQL Injection, XSS, CSRF, authentication vulnerabilities |
| API Security | Broken authentication, authorization flaws, insecure endpoints |
| Infrastructure Security | Misconfigurations, exposed services, insecure deployments |
| Network Security | Network exposure, insecure communication protocols |
| Data Security | Unauthorized data exposure, sensitive information leakage |
| AI Security | Prompt injection, insecure AI integrations, data leakage |
| Dependency Security | Vulnerable third-party libraries and dependencies |
| Access Control | Privilege escalation and authorization bypasses |

This list is illustrative and not exhaustive.

---

## 3. Reporting a Security Vulnerability

If you discover a potential security vulnerability in a QuantumX Labs project, we strongly encourage you to report it responsibly.

### Preferred Reporting Method

Use GitHub's **Private Vulnerability Reporting** feature or a GitHub Security Advisory, where enabled for the affected repository.

This allows security researchers to communicate vulnerability details privately with repository maintainers.

### Alternative Reporting Method

If private vulnerability reporting is unavailable, contact the organization through its officially published contact channels.
